
### 1. Общие положения

Данное техническое задание описывает требования к разработке статического класса `PasswordValidator` с методом `ValidatePassword` для проверки надежности пароля. Также предусматривается написание юнит-тестов для покрытия функционала метода `ValidatePassword` и последующее их преобразование в параметризованные тесты.

### 2. Требования к функционалу

#### 2.1. Класс `PasswordValidator`

*   **Тип:** Статический класс.
*   **Название:** `PasswordValidator`.

#### 2.2. Метод `ValidatePassword`

*   **Название:** `ValidatePassword`.
*   **Тип:** Статический метод.
*   **Входные параметры:**
    *   `string password`: Строка, представляющая пароль для валидации.
*   **Выходные параметры:**
    *   `ValidationResult`: Объект, содержащий результат валидации.

#### 2.3. Структура `ValidationResult`

*   **Тип:** Публичная структура (или класс) `ValidationResult`.
*   **Члены:**
    *   `bool IsSuccess`: Флаг, указывающий на успешность валидации ( `true`, если пароль соответствует всем критериям, `false` в противном случае).
    *   `string[] Errors`: Массив строк, содержащий описания ошибок, если `IsSuccess` равно `false`. Если `IsSuccess` равно `true`, массив должен быть пустым или `null`.

#### 2.4. Критерии валидации пароля

Метод `ValidatePassword` должен проверить входной пароль `password` на соответствие следующим критериям:

1.  **Минимальная длина:** Пароль должен быть не менее 8 символов в длину.
2.  **Максимальная длина:** Пароль должен быть не более 16 символов в длину.
3.  **Наличие заглавной буквы:** Пароль должен содержать как минимум 1 заглавную латинскую букву (A-Z).
4.  **Наличие строчной буквы:** Пароль должен содержать как минимум 1 строчную латинскую букву (a-z).
5.  **Наличие спецсимволов:** Пароль должен содержать как минимум 2 спецсимвола. Список допустимых спецсимволов: `!@#$%^&*()_+-=[]{};':"\|,.<>/?~`.
6.  **Наличие цифры:** Пароль должен содержать как минимум 1 цифру (0-9).

#### 2.5. Использование регулярных выражений

Для проверок на наличие определенных типов символов (заглавные буквы, строчные буквы, цифры, спецсимволы) допускается и рекомендуется использовать регулярные выражения.

### 3. Требования к тестированию

#### 3.1. Юнит-тестирование

*   Необходимо покрыть метод `ValidatePassword` юнит-тестами.
*   Ожидается **минимум 7 тестовых кейсов**, охватывающих различные сценарии валидации (успешные и неуспешные).

#### 3.2. Параметризованное тестирование

*   Каждый из разработанных тестовых кейсов должен быть преобразован в параметризованный тест.
*   Каждый параметризованный тест должен принимать **по 5 параметров** для покрытия разнообразных входных данных.

### 4. Технические требования

*   **Язык программирования:** C# (или другой по согласованию).
*   **Среда разработки:** Visual Studio (или другая по согласованию).
*   **Фреймворк для тестирования:** NUnit, xUnit, MSTest (или другой по согласованию).

### 5. Ожидаемый результат

1.  Реализованный статический класс `PasswordValidator` с методом `ValidatePassword`.
2.  Реализованная структура `ValidationResult`.
3.  Набор юнит-тестов, покрывающий основные сценарии работы `ValidatePassword`.
4.  Набор параметризованных тестов, каждый из которых использует 5 наборов входных данных.
5.  Проверенная работоспособность кода и тестов.

*   Полнота покрытия тестами (минимум 7 кейсов).
*   Правильность преобразования тестов в параметризованные с 5 параметрами.
*   Читаемость и структурированность кода.
*   Эффективность использования регулярных выражений.
